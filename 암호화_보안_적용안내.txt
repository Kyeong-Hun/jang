장일기 · 암호화/계정 보안 개편본
==============================

[적용 내용]
1. 신규 가입 비밀번호: 영문 소문자·숫자·특수기호를 각각 포함한 8자 이상
2. 신규 사용자 최초 로그인 및 이메일 인증 후 1회 복구 키 발급
3. 기존 사용자: 현재 서버의 평문 기록을 읽어 암호화 문서로 안전하게 전환
4. 기록 저장: 브라우저에서 AES-256-GCM 암호화 후 Firestore에 암호문만 저장
5. 기록 조회·통계·개인별 분석: 로그인한 브라우저에서 자동 복호화 후 기존 코드 실행
6. 새 기기: Firebase 이메일·비밀번호 로그인 시 해당 비밀번호로 암호화 키 자동 복원
7. 같은 기기에서 인증 세션 유지: IndexedDB에 저장된 비추출성 CryptoKey를 이용해 자동 복호화
8. 비밀번호 변경: 로그인 비밀번호 변경과 암호화 키 보호 변경 연동
9. 비밀번호를 잊어 외부에서 재설정한 경우: 처음 발급받은 복구 키를 사용해 기존 기록 복원
10. 프로필: 계정 및 보안 메뉴와 암호화 상태·비밀번호 변경·복구 키 설명 추가
11. 기존 홈, 배변·식사·생활 기록, 분석, 일러스트 7종 보존
12. JSON 수동 내보내기 기능은 기존대로 유지하지만 내려받는 파일은 평문이므로 경고를 표시함

[필수: Firebase 관리자 설정 / 배포 순서]
가. 출시 전 테스트용 계정으로 모든 절차를 시험하고 중요 기록은 사용자 본인이 백업하세요.
나. Firebase Console > Firestore Database > 규칙(Rules)에서 동봉한 firestore.rules를 붙여넣고 게시(Publish)하세요.
    - 이전 규칙은 schemaVersion 1 / 평문 payload만 허용하므로 새 HTML의 암호화 문서를 저장할 수 없습니다.
    - 새 규칙은 기존 평문 문서의 읽기와 암호화로의 이전을 허용하지만,
      모든 신규 생성 및 수정 문서는 schemaVersion 2 / vault 형태만 허용합니다.
    - 이전 버전의 웹 앱은 이 규칙 아래에서 기존 방식으로 기록을 저장하지 못할 수 있습니다.
다. Firebase Console > Authentication > 설정(Settings) > 비밀번호 정책(Password policy):
    - 최소 8자, 소문자 필수, 숫자 필수, 비영숫자(특수기호) 필수.
    - 기존 계정에 일괄 강제 비밀번호 변경을 적용하면 접속 장애가 생길 수 있으므로
      초기에는 기존 사용자에 대한 강제 업그레이드를 신중하게 검토하세요.
라. index.html 및 images/ 폴더를 함께 웹 호스팅 서버에 배포합니다. HTTPS에서 사용하세요.
마. 테스트 계정: 회원가입 -> 이메일 인증 -> 복구 키 복사/저장 -> 안내 확인 -> 기록 추가
    -> Firestore에 payload 평문 필드가 없고 vault.data.ciphertext만 존재하는지 확인
    -> 새 기기/다른 브라우저에서 동일 이메일·비밀번호로 로그인하여 기록이 복원되는지 확인
    -> 비밀번호 변경 후 다시 로그인, 외부 비밀번호 재설정 후 복구 키 시험.

[암호화 구현 상세]
- 데이터 키: CSPRNG로 생성한 사용자별 256비트 무작위 키
- 데이터 암호화: Web Crypto AES-256-GCM, 암호화마다 새로운 96비트 IV
- 키 보호: 사용자 로그인 비밀번호 -> PBKDF2-HMAC-SHA256 (60만 회, salt 128비트) -> AES-GCM으로 데이터 키 봉인
- 복구 수단: 사용자에게 처음만 표시하는 256비트 무작위 복구 키 -> HKDF-SHA256 -> 데이터 키 봉인
- 저장 내용: Firestore 문서에는 암호문·IV·KDF salt/설정·암호화된 키만 보관
- Argon2id가 아닌 PBKDF2를 사용한 이유: 외부 WASM/CDN 암호화 종속성을 새로 추가하지 않고
  웹 표준 Web Crypto로 단일 HTML에서 검증 가능하게 하기 위해서입니다.
  추후 검증된 Argon2id 구현으로 키를 재포장할 수 있지만 기존 문서 포맷 이전이 필요합니다.
- 암호화 키는 데이터 분석을 위해 브라우저 메모리에 있어야 하며, 정상 로그아웃 시 기기 내 저장 키를 제거합니다.

[중요한 제한]
- 웹 호스팅 운영자가 사용자에게 제공되는 JavaScript를 악의적으로 바꾸면 사용자 입력과 복호화된 기록을 탈취할 수 있는 구조적 한계가 있습니다.
- 기존 Firestore 문서는 해당 사용자가 로그인하여 마이그레이션하기 전까지 서버에 평문으로 남아 있습니다.
- 기존 서버 백업/다운로드 파일에는 평문이 남아 있을 수 있습니다. 복사본까지 소급 암호화되지 않습니다.
- 암호화 문서의 용량은 평문보다 커집니다. Firestore 문서 1MiB 한도를 초과할 경우 저장이 실패할 수 있습니다.
- 이 버전은 실제 Firebase 프로젝트에 자동 게시되지 않았습니다. 관리자가 규칙과 HTML 배포를 직접 완료해야 합니다.
- 이 실행 환경에서는 브라우저 자동 UI 테스트가 보안 제한에 막혀, 실제 서버/기기 간 시험은 별도로 필요합니다.
- 암호화·복호화/복구·변조 감지용 핵심 암호화 함수는 독립 테스트를 통과했습니다.
- 의학적 분석 알고리즘의 임상적 유효성은 검증된 것이 아닙니다.
